# 需求记录

## 背景

用户希望做一个面向 Galgame 的翻译器，参考现有小说翻译项目的批量翻译思路，但项目独立。目标不是截图/OCR 一句一句翻译，而是尽量直接获取游戏脚本文本，预先批量翻译，游玩时快速显示双语。

当前电脑没有 Galgame 样本。后续会在本地游戏电脑继续开发。参考对象可以是 9-nine- 系列、柚子社作品等常见日式 Windows 硬盘版 Galgame，但实际兼容性以目录结构和资源包格式为准。

## 用户偏好

- 翻译后端优先使用本地 Codex CLI，模型倾向 `gpt-5.5`。
- Codex CLI / Claude Code 是唯一需要联网的路径；工具本身不做线上服务。
- 暂不考虑手填 OpenAI/Claude API key。
- Qwen/Ollama 可作为后续本地 LLM 兜底，不是第一优先。
- 用户不会手动解包 Galgame，因此工具应允许选择 `exe` 或游戏目录并自动扫描。
- 展示方式倾向外置窗口双语显示。
- 不希望游玩时等 Codex 实时翻译；实时阶段应尽量本地查库即时显示。
- 翻译方向暂时只考虑日文到中文。
- 工具安装/开发目录、游戏目录、翻译工程目录必须区分开；程序不应把解包和翻译产物写回游戏目录。
- First UI should be CLI-first; desktop/window UI can come later.
- Translation should preserve the original Galgame style and tone.
- Runtime display should show translated Chinese only by default, because the game already displays the Japanese source.

## 核心需求

1. 选择游戏 `exe` 或游戏目录。
2. 自动扫描 exe 所在目录和常见子目录。
3. 识别常见资源/脚本形态：
   - `.xp3`
   - `.rpa`
   - `.rpy`
   - `.rpyc`
   - `.ks`
   - `.txt`
   - `0.txt`
   - `nscript.dat`
   - `scenario/`
   - `script/`
4. 能预提取文本时，生成统一台词条目。
5. 使用 Codex CLI / Claude Code 批量执行日译中。
6. 建立本地 `原文 -> 译文` 匹配索引。
7. 游玩时通过 Textractor/剪贴板获取当前原文。
8. 外置窗口显示原文和译文。
9. 未匹配时不阻塞 UI，可提示未匹配并可选后台补翻。
10. 无法提取的游戏输出诊断报告，说明识别到什么、卡在哪里、可用兜底方式是什么。
11. 记录可复用的解包配置；同类引擎/资源结构再次出现时，可复用已有配置。
12. 展示翻译进度，包括总条目、已翻译、失败、当前批次和可恢复状态。
13. 默认只翻译剧情文本，跳过系统设置、菜单、按钮、配置项等非剧情文本。

## 非目标

- 第一版不做游戏内文本框双语回写。
- 第一版不做所有引擎的通用解包。
- 第一版不做自研游戏进程 hook。
- 第一版不以 OCR 为主流程。
- 第一版不追求翻译补丁发布功能。
- 第一版不修改游戏目录，不保证生成可发布补丁。
- 第一版不做任何 DRM 绕过或加密封包破解承诺。

## 成功标准

- 用户无需懂解包，能选择一个游戏 exe/目录并得到扫描诊断。
- 对支持的脚本格式，能批量抽取台词并用 Codex 预翻译。
- 游玩时剪贴板出现当前原文后，字幕窗口能在本地快速显示双语。
- 常规命中路径不调用 Codex，避免明显等待。
- 所有导入失败都有可理解的错误信息和下一步建议。
- 翻译未完成不影响游戏启动；已翻译条目显示中文，未翻译或未匹配条目显示原文和状态。
